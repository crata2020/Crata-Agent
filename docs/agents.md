# CRATA 에이전트 구조

## 1차 MVP 활성 에이전트

### 1. CRATA CEO

전체 라우팅과 조율을 담당한다.

담당 업무:

- 사용자 요청과 추출된 작업 후보를 분류한다.
- 어떤 에이전트가 작업해야 하는지 결정한다.
- 적절한 워크플로우를 선택한다.
- 승인 필요 여부를 판단한다.
- 최종 결과를 요약한다.
- 작업 이력을 이해하기 쉽게 남긴다.

### 2. 개념수호자

공식 CRATA 지식과 개념 일관성을 담당한다.

내부 id: `concept_guardian`

담당 업무:

- 검사 개념과 유형 정의를 관리한다.
- 공식 CRATA 지식에서 근거를 제공한다.
- 초안이 공식 개념과 충돌하는지 확인한다.
- 공식 지식과 상담 사례 관찰을 구분한다.
- 공식 반영 후보를 승인 전 검토한다.

### 3. 결과지 에디터

검사 결과지 문구를 담당한다.

내부 id: `report_editor`

담당 업무:

- 검사 결과지 문구를 작성하고 수정한다.
- 성인, 청소년, 아동, 부모, 조직, 기관용 톤을 조정한다.
- 수정 전/후 문구를 만든다.
- 결과지 문구가 공식 개념과 맞는지 확인한다.
- 승인 가능한 형태로 산출물을 정리한다.

### 4. 상담 코치

유형 기반 상담 답변 초안과 챗봇 테스트를 담당한다.

내부 id: `counseling_coach`

담당 업무:

- 사용자 유형, 상대 유형, 관계 맥락을 바탕으로 상담형 답변을 만든다.
- 실제로 말할 수 있는 대화 문장을 제안한다.
- 내부 테스트용 챗봇 응답을 작성한다.
- 공식 지식을 직접 수정하지 않는다.

### 5. 사례학습가

상담 전사록 처리와 학습 후보 생성을 담당한다.

내부 id: `case_learner`

담당 업무:

- 상담 전사록을 보존하고 익명화한다.
- 사례 사실, 유형 정보, 감정, 행동, 관계 맥락, 패턴을 추출한다.
- 상담 내용을 공식 지식이 아니라 상담 사례로 저장한다.
- 검토용 학습 후보를 만든다.

### 6. 관계분석가

유형 조합과 상호작용 패턴 분석을 담당한다.

내부 id: `relationship_analyst`

담당 업무:

- 유형 조합을 분석한다.
- 관계 맥락별 패턴을 찾는다.
- 반복되는 상호작용 루프를 추출한다.
- 관찰된 패턴을 개입 후보와 연결한다.
- 향후 그래프형 관계 데이터로 옮길 수 있게 구조화한다.

### 7. 품질검수관

안전성, 톤, 형식, 승인 준비 상태를 담당한다.

내부 id: `quality_inspector`

담당 업무:

- 낙인적, 진단적, 단정적, 위험한 표현을 검토한다.
- 답변 형식과 길이를 확인한다.
- 승인 필요 여부를 확인한다.
- 승인되지 않은 공식 지식 변경을 막는다.
- 승인대기함에 들어갈 검토 의견을 작성한다.

## 확장 활성 에이전트

### 8. 사업설계자

제안서, 상품, 프로그램, 워크숍, 가격 구조, 기관 기획, 서비스 패키징을 담당한다.

내부 id: `business_designer`

담당 업무:

- 바로 제안서를 쓰지 않고 대상, 문제, 목적, 성과, 예산, 일정, 검사 활용 방식을 먼저 확인한다.
- CRATA 검사별 장점과 유형 구조를 기관/기업 문제에 맞게 연결한다.
- 프로그램 구성, 회차 설계, 예산 구조, 기대효과, 제안서 목차를 만든다.
- 필요한 경우 외부 근거와 문제 배경을 별도 리서치 후보로 남긴다.

### 9. 콘텐츠전략가

홍보, 유튜브, 블로그, 홈페이지 문구, 캠페인 아이디어, 콘텐츠 보고를 담당한다.

내부 id: `content_strategist`

담당 업무:

- 채널, 타깃, 핵심 메시지, 전환 목표, 금지 표현을 먼저 확인한다.
- CRATA 검사와 상담 사례를 고객이 이해할 수 있는 콘텐츠 주제로 바꾼다.
- 유튜브, 블로그, 홈페이지, SNS별 문체와 구조를 나눠 초안을 만든다.
- 성과를 비교할 수 있게 제목, 후킹, CTA, 후속 콘텐츠 후보를 함께 정리한다.

## 2차 확장 예정 에이전트

### 10. 운영비서

데일리 브리핑, 승인대기 요약, 작업 우선순위, 자동화, 향후 Telegram/n8n 연동을 담당할 예정 에이전트다.

내부 id: `operations_secretary`

## 에이전트 실행 상태

에이전트는 다음 실행 상태를 가질 수 있다.

- `idle`: 대기.
- `working`: 작업중.
- `reviewing`: 검수중.
- `waiting_for_approval`: 승인대기.
- `approved`: 승인됨.
- `rejected`: 거부됨.
- `error`: 오류.
- `disabled`: 비활성화.
- `planned`: 준비 중.

## 에이전트 설계 규칙

에이전트는 공식 지식을 몰래 수정할 수 없다. 에이전트는 초안, 후보, 검토 의견을 만들 수 있다. 공식 CRATA 지식이나 결과지 문구를 바꾸는 일은 승인된 워크플로우만 수행할 수 있다.

## 지식과 작업 가이드 연결

에이전트가 참조할 검사 지식과 작업 절차는 `knowledge/` 폴더에 둔다.

현재 기준:

- 공식 검사 지식: `knowledge/official/`
- 원본 보존 자료: `knowledge/_sources/`
- 에이전트별 작업 가이드: `knowledge/agent-guides/agent-operating-guides.md`

에이전트는 답을 바로 만들기 전에 다음 순서를 따른다.

```text
요청 분류
-> 부족한 정보 질문
-> 관련 MASTER 지식 확인
-> 에이전트 작업 가이드 확인
-> 초안 작성
-> 개념/톤/안전 검수
-> 승인 필요 여부 판단
```

사업설계자와 콘텐츠전략가는 활성 에이전트로 전환했으며, `agent-operating-guides.md`의 작업 프로세스를 프롬프트 컨텍스트로 연결한다. 운영비서는 자동화와 외부 알림 흐름이 안정된 뒤 활성화한다.
